# InputFlow G-POST：首版发布后的长时间运行与加固

> 日期：2026-10-02  
> 状态：计划于首个 release 实际发布后执行。  
> 用户决定：本任务不是 Phase F、G-PRE、H、RC 或首版发布的前置条件。

## 1. 目标与进入条件

基于已发布的实际二进制和配置，观察日常使用与长时间运行中 Hook／规则行为、资源趋势、日志增长、UI／IPC／系统状态恢复，再将缺陷修复进入后续 v0.9.x。

先完成首版发布；记录版本／tag／commit、包校验和、Agent／UI 实际路径、OS build、CPU、内存、显示器／DPI、鼠标设备、键盘布局、其他输入工具和配置摘要。用户配置可私下保存，公开证据只包含最小复现所需且已去除个人数据的内容。

使用真正发布的包；不得用随后修改的 Debug 版本跑完后宣称原发布版通过。如测试期间升级，建立新 session，分开记录前后版本。

## 2. 分阶段时长与计时口径

| 阶段 | 建议运行 | 用途 |
|---|---|---|
| POST-A | 约 1～2 小时真实工作 | 校验采样工具、日常误触发和初步增长趋势 |
| POST-B | 24 小时经过时间 | 白天／空闲／睡眠／恢复／开关 UI 的生命周期 |
| POST-C | 72 小时经过时间 | 更长资源趋势与跨日恢复，形成该版本长期证据 |

不是要求连续 72 小时操作鼠标。分别记录墙钟经过时间、Agent 存活区间、采样覆盖、系统睡眠／关机区间和有真实输入的区间。睡眠时无样本不等于采样成功；重启后的多 session 不能冒称单进程连续存活 72 小时。

允许自然使用累积，不要求用户改变电源设置、长期开启屏幕或让自己熬夜。未知／缺失时段必须留空并解释，不插值成“通过”。

## 3. 先改进采样工具

现有 `scripts/acceptance/sample-agent-resources.ps1` 的 `DurationSeconds` 上限为 86400（24 小时），固定 PID、首次 Pipe 连接和帧读取也不等于支持可靠的 72 小时采样。开始长测前核对并必要时新增 `scripts/acceptance/soak-agent-resources.ps1`，保留旧五分钟工具，避免影响历史复现。

长测工具必须：

- 支持 24／72 小时或分段 session；写明参数范围与实际 stop 条件。
- 正常采样间隔建议 10～30 秒，短负载窗口可临时更密；不能持续用高频 get_stats 测出采样器自身的负载。
- Pipe 连接、读／写有明确超时；断线、协议变化、Agent 退出和重连有界且可取消，不永久阻塞。
- 每个实例记录 PID＋启动时间／可执行路径，避免 PID 复用；重启开新 session、重新 handshake 并记录 reset。
- 逐行 flush、分段／轮转、上限和断点记录，避免无界单文件；程序或电脑意外退出仍保留已写数据。
- CPU 用时间差分，报告采样间隔、逻辑 CPU 数和是否按整机归一化；保留原始累计 CPU 时间。
- callback／output 累计计数跨进程不直接相减；分位是哪个窗口／滚动样本集必须准确说明，不能把每次 p99 平均当作全程 p99。
- 设置程序开关后重新识别真实实例，不能一直读取旧 Settings PID。
- 默认不记录文本／键序列／精确坐标；故障定位 debug 由用户显式短时开启、隔离记录并设置保留上限。
- 有问题时写错误行和上下文，不自动重启 Agent、关闭系统保护、修改配置或恢复 Active 以掩盖故障。

必要测试验证超时、断线／重连、停止和轮转；不需要模拟“等 72 小时”来测试时间参数。

## 4. 记录内容与观察操作

资源 CSV 包含 timestamp、session、PID／启动时间、working set、private bytes、线程、句柄、CPU 时间／差分、stats RTT、observed／callback 样本、callback 分位／max、output sent／failed／dropped、连接与错误状态。

按真实条件安排并在 observation 日志注明时间：

- 日常打字、浏览器、文件操作、复制粘贴和方向手势；至少每天有明确真实输入检查。
- 鼠标持续快速移动的有限窗口，分别在无方向规则、Active 规则和 Paused 状态观察。
- 设置程序开关、编辑／保存／启停及录制／预览取消。
- 正常发生的锁屏解锁、睡眠唤醒、显示器／DPI／布局变化；硬件不存在的项目保持未执行。
- 托盘／F12／UI 暂停恢复、Agent 正常退出／重开、可协调的 Explorer 重启。
- 其他常用输入工具共存；明确工具版本与配置，不把一次未观察问题当成普遍兼容。

没有真实输入时 IPC ready 和进程存活不能证明 Hook 在系统中仍安装。每天／恢复后用已知物理手势、observed 增量和目标行为交叉验证；没有官方可靠存活通知就不能凭空显示“Hook 永远正常”。

## 5. 判定和异常处理

考察 private bytes／句柄／线程是否在相同工作负载及完成清理后持续增长；working set 波动不直接判为内存泄漏。空闲 CPU、采样成本、日志磁盘增长与环境负载分开解释。保留尖峰和错误，不只提供平均数。

任何丢键／粘键／误消费／死锁／Hook 失效／配置损坏立即记录：版本、配置、时间、前台目标、手势顺序、暂停／恢复操作、最小日志和是否可复现。优先通过 F12／托盘／正常退出恢复；强杀所造成的历史输入不可恢复明确注明。

发现严重输入缺陷不等长测结束才修复。完成最小复现、原因假设、方案选择、确定性回归和短时物理验证，发布补丁版本后对新版本重新采样；旧版本失败记录保留，不因修复把它改成通过。

完整报告分三栏：已观察并通过、失败及修复、未执行／限制。POST-B／C 有中断时报告实际时长和 coverage；不做“72 小时稳定”标题却只给三天墙钟范围。
