## 3. M7 进入条件

以下七项原为 M7 正式接线的进入条件，现已完成现场记录：

1. Windows 菜单/按钮 release 墓碑：通过。
2. KeyChord、KeyMouseButton、Hold、HoldMouseButton 的成功、失败、暂停和队列满：通过。
3. 前缀失败回放紧跟新物理输入的目标观察顺序：通过。
4. 普通完整插入、提升目标零写入：通过；partial 未实机触发，明确保留限制。
5. 持续打字/点击与 stats 查询：Release 五分钟门槛通过。
6. 左右修饰、扩展键、中英布局、鼠标位置和已有 LeftShift：通过；keypad Enter 因无硬件未实测。
7. 正常退出等待墓碑释放的两秒内/外边界：两条分支均通过。

原始时序、目标消息、资源 CSV 和限制见联合验收记录；自动测试、无输入 smoke 与物理观察仍保持分栏，不相互冒充。

## 4. M7/M8 不变量

- agent 是唯一 Hook、规则验证、正式配置和热应用所有者。
- Named Pipe/UI 控制必须经过 Hook owner 的既有串行化边界，不能重新引入暂停超车。
- UI 周期读取诊断不得在 Hook 热路径持锁排序。
- 完整键盘扩展保留墓碑、repeat、timer、SendInput 诊断和原子配置语义。
- 鼠标 move 热路径只做无分配 O(1) 累计，不逐点日志或无界排队。
- F12 紧急旁路在设置断线、录制和配置错误时仍可用。

## 5. 收口结论

M6 的七项 Windows 人工进入门槛已完成，可作为 M7 Phase E 的可靠性基线。剩余项不是隐含通过：partial SendInput 无稳定物理触发源；keypad Enter 等缺失硬件未测试；同步 `SendInput` 没有 Windows API 最坏耗时保证。后续 Phase F/M8 必须继续遵守本节不变量。
