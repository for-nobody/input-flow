# ADR-001：组合匹配与回放协议（M4）

- 状态：已接受（Accepted）
- 日期：2026-09-26
- 涉及模块：`inputflow-engine`（rules / matcher / state / event）、`inputflow-windows`（platform / keymap）

## 背景（Context）

M4 需要实现 `Key+Key`、`Key+MouseButton` 组合匹配，以及无候选直通、失败回放、命中消费。规划稿第 11 节列出的"回放协议"与"按键状态"设计问题在本里程碑首次落地，需要固定决策。

## 候选方案（Options）

### 组合超时
1. 组合设显式等待超时（等待第二输入 T ms 后回放首键）。
2. 组合不设定时器，失败仅由"首键松开"或"第二输入不匹配"触发。

### 重叠前缀
1. 支持任意嵌套 / 重叠前缀。
2. MVP 仅单一活动前缀；重叠时先失败当前前缀再处理新事件。

### 规则模型
1. 把 `KeyChord` / `KeyMouseButton` / `Hold` 统一为 `Trigger` 枚举并预编译为 `RuleIndex`。
2. 保留 M3 的 `Rule::Hold`，组合另起模型。

## 取舍（Trade-offs）

- 组合不设定时器（选 1.2）简化状态机，但首键若被长期按住且无第二输入，则一直暂扣直到松开；时序语义留给 M5。
- 单一活动前缀（选 2.2）避免嵌套回放的顺序问题，代价是不支持重叠组合（已知限制）。
- 统一 `Trigger` + `RuleIndex`（选 3.1）让回调路径只需 O(1) 查询；代价是 M3 的 `Rule::Hold` 需迁移到新 API（有单测覆盖）。

## 实验 / 依据（Evidence）

- 纯引擎事件序列单测（31 项）覆盖：组合命中 / 失败、多候选竞争、无候选直通、注入直通、溢出旁路、暂停清理、冲突拒绝。
- keymap 往返测试（3 项）覆盖 VK↔Key 与鼠标消息映射。
- Windows 实机：`echo quit | probe-cli.exe` 安装 Hook 并以退出码 0 干净退出；组合交互（Ctrl+右键命中、Ctrl+Q 失败回放）待实机验证。

## 最终决策（Decision）

- 规则模型：`Trigger::{KeyChord, KeyMouseButton, Hold}` + `RuleIndex::compile`（拒绝重复 id / 重复 trigger）。
- 组合语义：首键按下暂扣；第二输入完成规则则消费并 `Emit` 动作；首键松开或不匹配则按序回放 `[首键, 第二输入]`。组合无显式超时。
- 状态：`KeyState` 与新增 `MouseState` 分别跟踪按键 / 鼠标按键的物理 / 已见 / 已消费。
- 平台：Win32 Hook / 消息循环 / `SendInput` 迁入 `inputflow-windows`；VK↔Key 映射放在 `keymap`（纯逻辑、可单测）；`Matcher` 在 Hook 回调内同步调用（`Send`、`Mutex` 静态、短临界区）。
- 回放 / 动作：通过 `Command::{Replay, Emit}` 交给工作线程 `SendInput`，带 `dwExtraInfo` 标记避免自触发。

## 后果（Consequences）

- 重叠前缀与组合超时暂不支持，需在 README 已知限制与 M5 / M6 处理。
- `inputflow-windows` 承担全部 `unsafe`；`probe-cli` 只做线程编排与规则定义。
