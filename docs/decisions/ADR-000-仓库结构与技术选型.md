# ADR-000：仓库结构与基础技术选型

- 状态：部分被取代（Partially Superseded）
- 日期：2026-09-26
- 修订：2026-09-27
- 涉及模块：全项目
- 后继：ADR-004 取代本 ADR 的桌面 GUI 选择

## 背景

InputFlow 是 Windows 全局键盘与鼠标输入组合引擎。M0 需要确定语言、Windows API、输入接入、配置格式和仓库结构。

本 ADR 最初曾把 Tauri 2 + React 作为后期 GUI 候选。该 GUI 决策已被 ADR-004 的“纯 Rust/Win32 agent + C#/WinUI 3 设置程序”取代；以下仍有效的基础决定继续作为项目基线。

## 决策

- 语言/工具链：Rust stable，Windows MSVC target。
- Windows API：`windows-sys`；平台 `unsafe`、句柄和线程生命周期集中管理。
- 输入接入：`WH_KEYBOARD_LL` + `WH_MOUSE_LL`，专用消息循环线程。
- 输出：`SendInput`，检查返回数量，以 `dwExtraInfo` 和 injected 标志识别本程序输入。
- 配置：serde + JSON，版本化、原子保存、坏文件恢复。
- 仓库：Cargo workspace；核心逻辑、配置、Windows 平台和应用入口分离。
- 桌面产品：当前决定见 ADR-004；旧 Tauri 方案仅是历史记录，不是构建依赖或实施要求。

## 后果

- 核心匹配器可脱离 Windows API 测试。
- Win32 不安全边界集中，便于审计和资源清理。
- agent 与设置程序通过版本化 Named Pipe 分离；设置窗口关闭不终止规则。
- M7 构建不需要 Web 前端工具链；WinUI/.NET/Windows App SDK 版本必须在 Windows 开发机实测记录。
