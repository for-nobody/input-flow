## 背景（Context）

M6 需要落实规划稿第 4 节（NFR-02/03/04/05）与 `Steps.md` 第 6 节的可靠性要求：暂停/旁路、配置验证、诊断日志、异常恢复与性能采样。此前 M5 遗留两个明确缺口（ADR-002「后果」）：

1. F12 紧急旁路只切换平台 `BYPASS` 标志，**不清洗 matcher 现有暂扣/活动状态**，会导致被吞掉的 down 裸露孤立 up（违反 NFR-04）。
2. 规则仍硬编码在 `probe-cli`，没有配置、坏文件回退与持久化（FR-07、NFR-03）。
3. 缺少崩溃/强杀后的提示、逐键日志默认开启（NFR-05 风险）、无性能基线（规划稿 4 节延迟预算）。

## 候选方案（Options）

### 配置模块位置
1. 把 serde 派生直接加进 `inputflow-engine`（打破其「零依赖」性质）。
2. 新建 `crates/inputflow-config`，依赖 engine 的公开类型 + serde/serde_json。

### 暂停/旁路语义
1. 暂停时只置标志，不清理状态（沿用 M5 行为，违反 NFR-04）。
2. 暂停/旁路时先 `set_paused(true)` 取出并回放已暂扣事件，再置 `BYPASS`；恢复时清 `BYPASS` 与 matcher 的 overflow bypass。

### 紧急组合
1. 单键（默认 F12，可配置）。
2. 多键和弦（回调内检测更复杂，MVP 收益有限）。

### 诊断日志
1. 逐键事件默认打印（现状，泄露输入内容）。
2. 结构化诊断（回放失败/超时/溢出/hook 状态）常开、匿名化；逐键事件放 `--debug` 后。

### 崩溃提示
1. 启动写 `running` 标记、干净退出删除，下次启动发现残留则提示（不承诺恢复已暂扣输入）。

### 性能采样
1. 平台 `Instant` 计时 + 有界蓄水池 `PercentileTracker`（最近 N 样本滑动窗口），报告 p50/p95/p99。

## 取舍（Trade-offs）

- 独立 `inputflow-config`（选 2）保持 engine 零依赖、跨平台单测不变；代价是新增一个 crate（成本可控）。
- 暂停时冲刷已暂扣事件（选 2）保证目标应用看到的 down/up 一致；代价是暂停瞬间会把正在暂扣的组合按序回放（符合「尽力回放、不承诺完全等价」）。
- 单键紧急键（选 1）实现简单、回调内 O(1)；和弦推迟到后续。
- 逐键日志移到 `--debug`（选 2）满足 NFR-05；默认日志仅含规则名、事件数、键名仅出现在 debug 采集。
- `PercentileTracker` 用滑动窗口截断样本，牺牲全局分布换取有界内存，足够用于基线测量。

## 实验 / 依据（Evidence）

- `inputflow-config` 9 项单测：合法解析、未知键/阈值范围/重复 id/保留组合冲突/规则冲突拒绝、坏 JSON 与缺失文件回退默认、原子保存往返。
- `inputflow-engine` 新增 4 项单测（键/按钮命名往返 1、PercentileTracker 3），合计 48 项；keymap 3 项；workspace 共 60 项通过。
- `cargo clippy --workspace --all-targets` 无警告。
- Windows 实机（`probe-cli.exe`，exit code 0）：缺失/损坏配置回退空规则旁路；`--config` 加载 1 条演示规则；`pause`/`resume`/`stats`/`quit` 生效；崩溃标记残留时启动告警、干净退出删除标记；`--print-default-config` 输出模板；`echo quit | probe-cli.exe` 干净退出。

## 最终决策（Decision）

- **配置**：新建 `crates/inputflow-config`；`Config { schema_version: 1, emergency_bypass_key, rules }`；键/按钮用 engine 的 `Key`/`MouseButton` `Display`/`from_name` 规范命名；`save` 写唯一 `*.tmp.<pid>.<seq>` → flush/sync → Windows `ReplaceFileW`（唯一 backup）。`load` 在正式文件无效时先按新到旧验证已提交 backup，再验证未提交 temp，全部失败才回退空规则/F12。成功/失败保存会尽力将 backup/temp 分别限制为 5/3 代；若限额内副本均损坏，则额外保留最新的已知有效副本。默认路径 `%LOCALAPPDATA%\InputFlow\config.json`，`--config` 覆盖。
- **校验**：类型、`timeout_ms ∈ [1, 60000]`、重复 id、未知键、保留组合（紧急键不得等于任何规则前缀键）、规则冲突（复用 `RuleIndex::compile`）；只把完整有效规则集交给引擎。
- **暂停/旁路**：控制台/未来 IPC 的 `suspend()`/`resume()` 进入有界等待的控制队列，由 Hook 消息线程执行并确认；F12 已在该线程，直接执行。暂停取出 pending、同步 `SendInput`、置 `BYPASS` 形成单一串行事务，确认包含 held/requested/inserted/complete/last_error；不会在 matcher 解锁与回放之间处理新物理输入。仍保留命中后 consumed Down 的释放墓碑；旁路期间除墓碑对应 repeat/Up 外均直通。干净退出在同一线程冲刷并最多等待 2 秒排空墓碑。
- **紧急组合**：可配置单键（默认 F12），校验不与规则前缀冲突。
- **诊断日志**：`replay`/`matched`/`timeout`/`queue_overflow`/`sendinput_failed`/hook 状态常开；逐键事件仅在 `--debug` 下输出。
- **异常恢复**：`running` 标记（含 PID）启动写、干净退出删；下次启动残留则提示「上次异常终止，已暂扣输入不承诺恢复」。
- **性能采样**：`inputflow-engine::stats::PercentileTracker`（有界滑动窗口 + nearest-rank 分位）；查询在锁内复制最多 100,000 个 `u64`，锁外排序一次并同时计算 p50/p95/p99/max。回调观测从入口计至取得记录锁，包含 Matcher/统计锁等待、同步输出及转发路径的 `CallNextHookEx`，但不包含其后的样本写入/解锁，故不称为不可完整自测的“完整 wall time”。`stats` 另报告查询本身耗时；真实阈值仍以 Windows 高负载样本决定。

## 后果（Consequences）

- 缺失/损坏配置可启动并默认旁路；规则出错后用户仍可用紧急键或 `pause`/`quit` 关闭拦截。
- 逐键文本默认不再进入日志；调试须显式 `--debug`。
- 性能基线已可测；周期 `SetTimer` 请求值为系统最小 10ms，实际 `WM_TIMER` 可延后。精确一次性计时器仍留待真实基线决定。
- 托盘暂停与 GUI（M7）必须复用带完成确认的 `suspend`/`resume`，不得绕过 Hook 线程直接修改 matcher/BYPASS；本轮不引入原生托盘。
