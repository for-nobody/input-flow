# ADR-009：首版分发与用户生命周期

- 状态：已接受
- 日期：2026-10-09
- 范围：首个 Windows x64 公开测试版
- 关联：[`../tasks/FIRST_RELEASE.md`](../tasks/FIRST_RELEASE.md)、ADR-004、ADR-006、ADR-008

## 背景

开发构建依赖本机 SDK 和已安装 Windows App Runtime，不能直接证明普通用户可部署。首版需要一个
不改变 Agent／Settings 架构、无需管理员安装、可以从任意目录运行，并有透明自启动、升级和移除
流程的最小交付方案。

## 方案比较

| 方案 | 体积／依赖 | 权限与兼容 | 更新／移除 | 结论 |
|---|---|---|---|---|
| Unpackaged、framework-dependent | 最小；目标机另装 .NET Desktop Runtime 与 Windows App Runtime | 可免管理员运行，但前置 runtime 安装可能需要额外部署协调 | 程序目录小；共享 runtime 不随应用移除 | 保留为明确依赖 fallback，不作为默认 zip |
| Unpackaged、双 self-contained | 目录约数百 MiB；随包携带 .NET 与 Windows App SDK | x64、无包身份、普通用户目录可运行；仍依赖 Windows 系统组件 | 整包切换目录；删除程序目录即可 | **首版选择** |
| 用户级 installer | 可包装上述目录并做快捷方式／卸载 | 需要新增安装技术、签名与更多生命周期面 | 体验更完整，但增加首版风险 | 后续可选，不阻塞首版 |
| MSIX／商店 | 包身份、声明式安装与更新 | 涉及证书、签名、包注册和渠道约束 | 平台管理升级／卸载 | 首版不选 |

## 决定

1. 发布 `unpackaged` Windows x64 便携目录 zip；Agent 与 Settings 同目录，确保托盘按自身目录定位
   `InputFlow.Settings.exe`，不依赖当前工作目录。
2. Settings 同时启用 `.NET PublishSelfContained` 与 `WindowsAppSDKSelfContained`。两者独立验证；
   首版不使用 trim、single-file、AOT 或 ReadyToRun 优化，以降低反射、资源和首次提取风险。
3. Agent 继续是纯 Rust／Win32 GUI 进程，不加载 .NET。PE imports 证明 Agent 依赖
   `VCRUNTIME140.dll`；首版明确要求安装受支持的 Microsoft Visual C++ Redistributable x64，采用可
   服务的中央部署，不从开发机或 System32 偷拷 DLL。移除 InputFlow 时不删除共享运行库。
4. 程序目录只放不可变产物和用户说明；配置、备份和日志继续位于
   `%LOCALAPPDATA%\InputFlow`。包内不放用户配置、完整输入日志、PDB 或测试输出。
5. 登录自启动默认关闭。包内脚本只管理当前用户 Startup 中的 `InputFlow Agent.lnk`，目标为当前包
   的 Agent、工作目录为包目录；操作幂等，只删除自己识别的 InputFlow 入口，不创建服务或高权限任务。
6. 升级采用“正常退出旧进程 → 完整解压新目录 → 保留数据 → 更新自启动 → 启动核对 → 删除旧目录”。
   禁止在运行时逐文件覆盖。Schema v4 不承诺向旧版降级；旧版不得静默保存或破坏新方向规则。
7. 移除先正常退出和禁用自启动，再删除已确认的程序目录；默认保留专属用户数据，按用户明确选择
   才删除。绝不移除共享 runtime。
8. 声明最低 TFM／manifest 版本不等于真实兼容证据。发布说明只承诺 H 干净环境实际覆盖的 Windows
   x64 范围；没有独立环境时相应 DIST 项保持未完成。

## 代价与后果

- 发布目录显著增大，每次更新携带完整 runtime；换来 zip 解压即用且不要求单独安装对应 .NET／
  Windows App Runtime。
- 便携包没有自动更新、安装器回滚、包身份或商店信任；自启动路径在目录移动后必须显式刷新。
- 未签名公开测试包可能触发来源／信誉提醒。不能要求用户关闭系统保护；发布页必须提供 SHA-256。
- .NET self-contained 固定构建时 runtime patch，安全更新需要重新构建并发布整个应用包；共享
  Visual C++ Redistributable 则由 Microsoft 的中央部署独立服务。

## 实施约束

- `scripts/package-release.ps1` 是唯一目录包入口，默认先执行完整构建门槛；任一步失败返回非零。
- 发布只针对 Settings 项目和明确 profile，不向 solution 传已知无效的 RID／Platform 组合。
- profile 固定 `win-x64`、双 self-contained、目录发布、不裁剪、不单文件。
- H 验证空格／中文路径、任意工作目录、单实例、托盘打开 Settings、自启动、升级和移除；RC 再对
  固定最终版本包做有限 smoke 与校验和核对。
