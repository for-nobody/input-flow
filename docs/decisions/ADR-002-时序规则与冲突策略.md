# ADR-002：时序规则与冲突策略（M5）

- 状态：已接受（Accepted）
- 日期：2026-09-26
- 涉及模块：`inputflow-engine`（rules / matcher）、`inputflow-windows`（platform / windows）

## 背景（Context）

M5 需要实现 `Hold(K,T)`、`Hold(K,T)+Button(B)` 与独立长按单键，并处理阈值边界、按键自动重复、冲突。规划稿第 3.1 节固定了基本语义：`Hold(K,T)` 从物理 `K down` 计时到 `T`，重复 down 不重置计时，`T` 前释放不命中；`Hold(K,T)+Button(B)` 需在 `T` 后且 `K` 仍物理按住时发生 `B down` 才命中，MVP 不允许“先按 B 再达到 T”。

同时发现一个关键缺口：`Matcher::on_timeout` 在纯引擎单测中由 `ManualClock` 驱动，但平台层从未在真实运行中调用它，导致 `Hold` 规则无法在 Windows 上真正触发。M5 必须补齐平台层的计时器驱动。

## 候选方案（Options）

### 平台计时器
1. 消息循环线程上挂周期 `SetTimer`，在 `WM_TIMER` 里轮询 `Matcher::poll_timeouts()`。
2. 用 `MsgWaitForMultipleObjectsEx` / 可等待计时器做精确的一次性调度。

### 冲突检测范围
1. 仅按 5.4 字面实现：单键 `Hold{K}` 与同前缀复合规则冲突。
2. 更宽泛：一个前缀键最多属于一种“规则种类”（单键 Hold / 和弦组 / Hold+MouseButton）。

### 单一活动前缀下的歧义
- `HoldMouseButton{K,...}` 与 `KeyChord{K,...}`/`KeyMouseButton{K,...}` 共享前缀时，首键只能启动一种活动状态，会静默误路由。

## 取舍（Trade-offs）

- 周期 `SetTimer`（选 1.1）实现简单、回调路径不变；代价是每约 5ms 唤醒一次消息循环（250ms 阈值下抖动 ≤2%）。精确一次性调度（选 1.2）更省电但增加重调度复杂度，推迟到 M6 性能采样时再评估。
- 宽泛冲突（选 2.2）避免静默误路由，符合“MVP 不暗中选优先级”；代价是把少量理论上可组合的规则判为冲突（均为已知限制，写入 README）。

## 实验 / 依据（Evidence）

- 纯引擎事件序列单测新增 13 项（合计引擎 44 项），覆盖：`Hold` 精确阈值 / 阈值前释放、重复 down 不重置计时、`HoldMouseButton` 阈值前按 B 失败、阈值后匹配并消费 B up 与 K up、阈值后非匹配按钮失败、armed 后 K 松开失败、`poll_timeouts` 到期判定、三类冲突拒绝。
- `cargo test --workspace`：44（引擎）+ 3（keymap）= 47 项通过；`cargo clippy --workspace` 无警告。
- Windows 实机：`echo quit | probe-cli.exe` 安装 Hook、显示 M5 横幅、退出码 0；交互按键（按住左 Ctrl ≥250ms 后右键）需人工实机确认。

## 最终决策（Decision）

- 规则模型：新增 `Trigger::HoldMouseButton { key, timeout_ms, button }`；`RuleIndex` 增加 `hold_buttons`（每键至多一条）与 `has_hold_button`/`hold_button` 查询。
- 匹配器状态：新增 `Active::HoldToButton`，分“等待阈值”与“已武装（armed）”两阶段；`on_timeout` 在阈值到达且 `K` 仍按住时仅武装（不产出命令），此后 `B down` 才命中。`next_deadline` 在 armed 后返回 `None`。
- `HoldMouseButton` 语义：活动期间任意鼠标按钮 down 都是决定性的——armed 且为该规则按钮则匹配消费，否则失败回放（MVP 不允许早于 `T` 的按钮）。其它按键直通；未消费的按钮 up 直通。
- 冲突策略（宽泛）：一个前缀键最多属于一种规则种类；具体拒绝 ① 单键 `Hold{K}` 与同前缀复合规则，② `HoldMouseButton{K}` 与 `KeyChord{K}`/`KeyMouseButton{K}`，③ 同键多条 `HoldMouseButton`。
- 平台计时器：周期 `SetTimer`（5ms，`WM_TIMER`）驱动 `Matcher::poll_timeouts()`；回调保持轻量，计时在消息循环线程（回调之外）处理。

## 后果（Consequences）

- 重叠前缀仍不支持（ADR-001 延续）；`HoldMouseButton{K}` 与同前缀和弦在 MVP 判为冲突。
- F12 紧急旁路目前只切换平台旁路标志，不清洗 matcher 现有暂扣/活动状态；这是 M6“暂停/旁路”要处理的事项。
- 精确可等待计时器、性能采样（p50/p95/p99）留待 M6。
