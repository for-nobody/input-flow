# ADR-008：鼠标方向规则与直通策略

- 状态：已接受（Accepted）
- 日期：2026-10-08（Australia/Brisbane）
- 涉及模块：`inputflow-engine`、`inputflow-config`、`inputflow-windows`、`inputflow-protocol`、`InputFlow.Settings`
- 前置：ADR-001～007；不改变单候选、回放、Hook owner、同步输出和 Agent 配置权威

## 背景与选择

首个公开测试版需要“按住键盘激活键后向左／右／上／下移动鼠标”的规则。候选算法包括路径总长度、Raw Input 相对位移、屏幕坐标净位移。首版选择 **`WH_MOUSE_LL` 的屏幕坐标净位移**：它能复用现有 Hook owner 和 `MSLLHOOKSTRUCT.pt`，不增加设备身份或 Raw Input 架构，也不会把抖动、绕圈误算成方向距离。

鼠标 move 永远直通 Windows。InputFlow 不缓存、回放或修正轨迹，不调用 `SetCursorPos`，命中时只输出既有 `Action::KeyChord`。Microsoft 文档说明低级鼠标回调在事件进入线程输入队列前收到消息，`MSLLHOOKSTRUCT.pt` 是 per-monitor-aware 屏幕坐标；回调必须快速返回。因此仅在存在方向规则时规范化 move，热路径只更新固定大小状态，不逐点记录或发送 IPC。

## 坐标、时间和边界

1. 激活键首次非 repeat 的物理 Down 到达 Hook owner 时调用 `GetCursorPos`，成功返回的屏幕坐标就是起点。不能取得起点时该次 Down 直通且不启动方向候选；不会用第一次 move 代替起点。
2. move 使用 `MSLLHOOKSTRUCT.pt`。单位统一为屏幕像素，x 向右、y 向下；Left 为负 x，Up 为负 y。差值先扩展为有符号 64 位，再求绝对值，允许多屏负坐标和跨原点，不发生 i32 减法溢出。
3. 只计算 `current - origin` 的净位移。绝对 x、y 相等时不确定方向；否则绝对值更大的轴是唯一主轴。主轴达到 `min_distance_px`（等于即满足），偏轴不超过 `off_axis_tolerance_px`（等于即满足）才可命中。偏轴超标、距离不足、折返、抖动或未配置的方向继续等待释放／取消／超时，不依 JSON 顺序选择另一条规则。
4. 时间使用 matcher 的单调 `Instant` 时钟。move 在 owner 顺序中先于超时处理且时间恰等于 deadline 时可命中；超时消息先处理则取消，二者由既有单线程顺序确定。晚于 deadline 的 move 会主动取消，即使 `WM_TIMER` 投递延迟。睡眠后单调 elapsed 已超过窗口，旧候选不能继续命中。
5. 配置合法范围：`min_distance_px=10..2000`、`max_duration_ms=100..5000`、`off_axis_tolerance_px=0..2000`。UI 默认分别为 `80 px / 500 ms / 40 px`。500 ms 默认值在常见键盘 repeat 延迟下给有界 FIFO 留出余量；用户选择更长窗口时仍受 16 项 FIFO 保护，溢出按既有安全旁路处理，不丢弃第 17 项后继续假装候选有效。

这些像素受系统鼠标速度、加速度、DPI、屏幕边缘和跨 DPI 布局影响，不代表毫米或设备原始 counts。负坐标自动测试不等于多显示器热插拔／跨 DPI 实机证明。

## 激活键与事件归属

方向候选复用现有 pending FIFO 和 release tombstone：

| 路径 | 激活 Down／repeat | 当前鼠标 move | 激活 Up |
|---|---|---|---|
| 候选中 | 暂扣；repeat 原序进入有界 FIFO | 直通 | 暂扣后与 Down／repeat 原序回放，候选结束 |
| 命中 | pending 清除并消费；先建立 release tombstone 再输出 | 直通 | 消费并清除 tombstone |
| 超时／注入跳变／wheel 取消 | 已暂扣流先回放；仍按住时不重新武装 | move／wheel 直通 | 直通，形成回放 Down 的对应 Up |
| 其他非 repeat 键 Down／鼠标按钮 Down | 当前输入与激活流按序暂扣并回放 | 不适用 | 后续直通 |
| pause／F12／replace／quit | 由 Hook owner 冲刷 pending；已命中 tombstone 保留 | 直通 | 按既有 drain 规则 |
| FIFO 满／输出 0 或部分插入 | 进入既有安全旁路并记录不完整恢复 | 直通 | 只在能够证明归属时处理 |

候选失败、取消或超时后，即使激活键仍按住，repeat 和后续 move 都不能重新武装；必须先看到匹配的真实 Up，再由下一次非 repeat Down 建立新候选。命中后继续移动也不再次输出。

## 多方向、身份和冲突

- 配置仍以“每方向一条规则”保存；同一 logical／physical 激活 identity 最多四条，预编译成一个固定四槽组。move 不随总规则数线性扫描。
- 同键同方向重复拒绝；同组所有启用规则必须使用完全相同的距离、时间窗和偏轴容差。禁用规则仍需字段合法，但按 ADR-007 不参与运行时组冲突；重新启用时 Agent 验证整份草稿。
- direction 与 `Hold`、`KeyChord`／`KeyMouseButton` 组、`HoldMouseButton` 共享首键时按 ADR-002 跨类型拒绝，不引入暗中优先级。单候选语义不变。
- 一个事件同时匹配 exact physical 与 logical identity 时继续 physical-first。紧急旁路键仍不能成为任何启用规则前缀。
- 斜线只由绝对净位移较大的轴决定；主轴相等不命中。因此结果不依 HashMap 或 JSON 顺序。

## 注入、跳变和输出

自身 `dwExtraInfo` 标记的注入在进入 matcher 前直通，不能递归触发。其他带 `LLMHF_INJECTED` 的 move 不驱动命中，并取消当前方向候选、回放激活流，防止下一次物理 move 使用跳变前的旧起点。注入 Up 仍不能清除真实物理 tombstone。

低级 Hook 不能可靠识别所有没有 injected 标记的第三方／系统光标跳变，这是公开限制。动作继续走现有同步 `SendInput` 完整／零／部分插入报告；方向 match 与 timer 路径都在调用输出前释放 matcher 锁，并在允许重入前写好一次性状态。

## Schema、协议和 UI

正式配置升级为 **Schema v4**，新增严格 trigger：

```json
{
  "type": "mouse_direction",
  "key": { "match": "logical", "key": "F8" },
  "direction": "right",
  "min_distance_px": 80,
  "max_duration_ms": 500,
  "off_axis_tolerance_px": 40
}
```

v1／v2／v3 继续严格读取并只在内存中迁移为 v4；新保存只写 v4。`enabled`、规则顺序、键身份和动作不变。wire envelope、frame 和 method 没变，因此 Named Pipe 保持 protocol v1；handshake 改报 `schema_version=4` 和 `config_v4`，不支持方向结构的旧 UI／Agent 会明确拒绝，不会静默删除规则或用旧草稿覆盖。

现有 WinUI 编辑器增加方向、距离、时间窗和偏轴字段。Agent 仍是 validate／apply 权威。UI 的有限预览显式开始、可取消、按所填时间窗自动停止；它只轮询当前屏幕坐标并显示方向／净位移／进度，不保存轨迹、不执行动作，并明确由“开始”按钮替代本次临时激活。预览算法只是非权威反馈，正式行为由 Rust matcher 和 Agent 校验决定。

## 后果与验证

- 普通 move 在没有方向规则、没有激活中的方向候选或处于旁路时保留无 matcher 锁的快速直通；只有激活键候选期间每点进入一次有界锁和固定大小计算，无逐点 heap allocation／日志／IPC。
- 自动测试必须覆盖四方向阈值、净位移／折返、偏轴、相等主轴、时间边界、一次命中、repeat／overflow、输入取消、pause／replace、logical／physical、注入、负坐标及 125／500／1000 Hz 合成序列。合成频率不是物理 polling rate 证据。
- UI／跨语言 fixture／handshake／保存读回必须同步验证。真实四方向、拖拽直通和五分钟物理 move 仍需按 F-PHY-01～07 单列记录；缺少物理或多屏硬件时不能用自动测试冒充。
