# 触控板 Stage 5 · 数字键盘执行记录

2026-11-20（Australia/Brisbane）。开发基线为 `main` 的 `124c7e5`，Agent 正式配置为 Schema v6。开工时工作树只有未跟踪的 [Stage 5 任务卡](../tasks/TOUCHPAD_STAGE_5_NUMPAD.md)。

## 初始取舍

- 布局为固定三列四行，使用 HID 描述符的两轴闭区间。格间整条留白占单格宽或高的 8%，在内部分界线两侧各取 4%，靠数字一侧的留白端点也归为留白。外缘可命中边缘数字，最大坐标落在最后一列或最后一行。下排左右的空白格取消旧候选，窄缝允许回到原格。无效坐标或描述符跨度拒绝识别。
- 采用一次接触、一次明确抬手提交。每份报告参与跨格判定。进入或中断后，旧接触须离开，重新落指才可选键。
- 正式开关默认关闭。初始绑定采用 `F9` 双击进入、`F10` 双击退出，留出 Stage 4 的左右 Ctrl 和 Alt+1～5。绑定在 Agent 校验时与当时的普通规则、演示绑定和实际旁路键一起检查。默认提示显示到第一次完整提交。
- 先用只读路径验证 HID 意图与原生焦点行为。已有 Stage 3 证据显示原生轻点有时会向指针目标发送按钮消息。正式路径先以已明确关闭 Windows 单指轻点为输出条件，并在提交前复查前台、键盘焦点与修饰键。相关设置由操作者按需要手动切换。

本机为 ASUS Zenbook 14 UX3405MA、Windows x64 `26200.9974`，读到一台可解码 Precision Touchpad。交互桌面只读试次（03:03:16～03:03:27，`target/stage5-desktop-20261120-025718/`）中，Windows 单指轻点为开启（`TapsEnabled=0xffffffff`）。两框起初均空，左框有焦点，蓝牙鼠标指针悬停在右框。第一次触碰的 5 意图仍关联左框，紧接着右框收到未标记左键并取得焦点。后续 0 因按钮状态取消，第二次 5 意图关联到了右框。三对原生左键均落在右框，试次末焦点在右框，两框为空，合成输出为零。较早一轮从右框开始，未计入左焦点对照。

### 5B／5C · 产品接入

正式使用前在 Windows「蓝牙和设备 → 触摸板 → 轻点」手动关闭「单指轻点以单击」，试验后可原路恢复。Agent 在进入和提交时确认设置关闭。每次接触记录前台窗口和原生键盘焦点句柄，监听前台及焦点事件，并在键盘或按钮活动时作废旧候选。Agent 通过带自身标记的 `VK_NUMPAD0`～`VK_NUMPAD9` 按放尝试交付数字，零或部分提交走现有旁路与单次释放修复。

Schema v7 持久化 `numpad.enabled`、`start`、`stop` 和 `guide`。Settings 沿用规则编辑和跨页草稿，能与 v4～v7 对应 Agent 配对。内置模式绑定复用规则索引的冲突校验，启用规则计数仅统计普通规则。Named Pipe 继续使用协议 v1，能力为 `touchpad_numpad`。状态包括确认、取消、请求、插入及取消原因。

### Num Lock 兼容性复验

2026-11-20，基线 `127f9d9`。用户实际使用时发现，旧版在记事本中可输入数字，Windows 计算器在 Num Lock 关闭时会把板面 2、4、6、8 当成方向键。使用屏幕键盘开启 Num Lock 后，计算器可输入数字。

触控板数字输出改用键盘顶排的非扩展扫描码，板面 2 发送 `0x03`。每次完整接触仍经原有焦点、修饰键和设备复核，然后提交一对带 Agent 标记的按键和抬键。Num Lock 状态由系统保留。普通规则的 `Numpad0`～`Numpad9` 逻辑键身份保留原有语义。

`scripts/build-windows.ps1 -SkipRestore` 通过。新增的回归测试检查 0～9 每个数字的扫描码、按放标志和 Agent 标记。Rust 工作区 201 项通过，1 项交互覆盖层测试按默认设置略过。

同一台 ASUS 笔记本使用隔离测试 Agent（PID 34344）。Windows 单指轻点已关闭，试验配置关闭 Touch Click 和激光笔。操作者用屏幕键盘设置 Num Lock，分别在清零的计算器和空白记事本中实地点触板面 2。
