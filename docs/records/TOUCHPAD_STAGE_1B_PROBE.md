## 描述符实测

在解码实现前调用 `GetRawInputDeviceInfoW(RIDI_PREPARSEDDATA)` 和 `HidP_Get*Caps` 读取本机描述符。
输入报告 ID `0x54`，总长 43 字节。link `0` 为触控板顶层集合，link `1`～`5` 为 Finger
集合（`0x000D/0x0022`），各自包含完整的一组接触字段。

| 字段 | Usage Page／Usage | Link | 类型及逻辑范围 |
|---|---|---|---|
| Contact Count | `0x000D/0x0054` | `0` | 4 位，`0..5` |
| Contact ID | `0x000D/0x0051` | `1`～`5` | 4 位，`0..10` |
| Tip Switch | `0x000D/0x0042` | `1`～`5` | HID button，`0` 抬起，`1` 接触 |
| X | `0x0001/0x0030` | `1`～`5` | 16 位绝对值，`0..3996` |
| Y | `0x0001/0x0031` | `1`～`5` | 16 位绝对值，`0..2242` |

解码按实际报告 ID、长度及 Contact Count 选择有效槽位。`Contact Count=1` 时，本机并行报告的有效字段
同在第一个槽位（link `1`）。同一设备上从已观察的 Tip 置位追踪到同一 Contact ID 的明确 Tip 清除。
空报告、无关报告、采样结束、失焦和多指帧各有独立处置，只有匹配的 Tip 清除会产生 `UP`。
持续时间取两次报告进入探针时的单调时钟差。起止坐标均为触控板表面逻辑单位。
[Windows Precision Touchpad Collection](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touchpad-windows-precision-touchpad-collection)

## 复现与自动验证

在 Rust／MSVC x64 开发环境中执行：

```powershell
cargo run --locked --manifest-path .\experiments\touchpad-probe\Cargo.toml -- --describe
cargo run --locked --manifest-path .\experiments\touchpad-probe\Cargo.toml
```

`1`～`4` 保留原报告计数模式。`5`、`6`、`7` 分别采集短触、静止约一秒、从左向右慢滑。
`Enter` 结束当前组，`Esc` 关闭窗口。可执行文件同目录的 `touchpad-probe-*.log` 包含各组计数和接触摘要。

离线 Windows 构建、格式检查、严格 Clippy 与 5 项单测通过。单测用一次人为拉长到 1 秒的报告间隔
验证接触仍保持，随后收到匹配的 Tip 清除才输出 `UP`。单测也覆盖 Contact ID 重用、空帧和多指中断。

**1B 结论**　这台机器的前台报告足以恢复以上单指接触的起止、设备坐标和观测时长。
跨设备、后台、原生轻点和双指滚动没有在本轮单独验收。探针保持只读，Agent 和系统触控板设置未改动。
