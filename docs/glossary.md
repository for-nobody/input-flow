# InputFlow 术语表（Glossary）

> 本文统一 InputFlow 文档与代码讨论中使用的术语，避免歧义。
> 术语给出中英文对照；程序代码中的标识符一律使用英文。

## 事件与输入

- **物理按住（physical held）**：物理键盘/鼠标按键当前是否被用户实际按住。区别于“目标应用已看到”的状态。
- **可见按键状态 / 目标已看到（seen by target）**：目标应用已经接收到并“看到”的按键按下/松开状态。回放、消费与旁路都以“让目标应用看到的顺序与状态尽量接近物理输入”为目标，但不承诺完全等价。
- **事件归一化（event normalization）**：把 Win32 低级 Hook 的结构（`KBDLLHOOKSTRUCT` / `MSLLHOOKSTRUCT`）转换为引擎内部统一的 `InputEvent`（来源、虚拟键、扫描码、左右/扩展标志、按下/松开、单调时间戳、顺序 ID、注入标志、鼠标按键/滚轮）。
- **注入标志（injected flag）**：低级 Hook 结构中的 `LLKHF_INJECTED` / `LLMHF_INJECTED` 标志，表示该事件由合成输入（`SendInput` / `keybd_event` / `mouse_event`）产生。
- **dwExtraInfo 标记（dwExtraInfo tag）**：本程序在 `SendInput` 时写入 `dwExtraInfo` 的唯一标记，结合 injected 标志识别“本程序生成的事件”，避免自触发递归。

## 决策与状态

- **候选前缀（candidate prefix）**：某事件能否构成任意“已启用规则”的前缀。无候选的事件直接放行，绝不暂扣。
- **直通（pass-through）**：事件不拦截、不暂扣，直接传给系统/目标应用。
- **暂扣（pending / hold）**：对可能构成已启用规则前缀的事件，先不传给目标应用，暂存起来等待后续事件或超时再做决定。
- **回放（replay）**：匹配失败或超时后，按顺序把暂扣事件重新注入（`SendInput`）给目标应用；只“尽力回放”，不承诺完全等价。
- **消费（consume）**：命中规则后，吞掉触发该规则的下/上事件（不传给目标应用），改为发送规则定义的动作；任何已消费的 down 不可把其 up 裸露给应用（NFR-04）。
- **命中（matched）**：事件序列满足某条启用规则，触发一次动作；同一触发只执行一次。
- **动作（action）**：命中后发出的键盘/鼠标输出（如 `Ctrl+C`）。
- **旁路（bypass）**：不拦截、不暂扣、直接放行的状态；也指暂停、故障、配置无效、溢出时进入的安全状态。

## 队列与边界

- **有界暂扣（bounded pending）**：暂扣队列有容量上限；到上限时旁路新事件并尽力冲刷已有事件（NFR-02）。
- **溢出（overflow）**：暂扣队列达到上限的边界情形。
- **超时（timeout）**：规则对“按住时长/等待第二输入”设的期限；到期限未命中则按序回放。

## 平台与安全

- **低级 Hook（LL hook）**：`WH_KEYBOARD_LL` / `WH_MOUSE_LL` 全局低级键盘/鼠标钩子；回调需快速返回，否则可能被系统静默移除。
- **专用消息循环线程（dedicated message-loop thread）**：承载 Hook 与消息循环的独立线程，保证清理顺序与回调快速返回。
- **SendInput**：合成键鼠事件并注入系统输入流的 Win32 API；受 UIPI 完整性级别限制，且不会重置现有键盘状态。
