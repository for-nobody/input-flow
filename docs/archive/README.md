# InputFlow 文档归档

> [!CAUTION]
> 本目录只保存历史证据和已完成任务。任何文件中的“当前状态”“下一步”、旧路径、旧行号或旧测试
> 数量都只代表记录产生时的快照。项目当前进度只看
> [`../status/CURRENT_STATUS.md`](../status/CURRENT_STATUS.md)。

## 目录

| 目录 | 内容 |
|---|---|
| `handoffs/` | 已完成职责的文档交接和一次性执行入口 |
| `plans/` | 被当前规划取代的历史全阶段计划 |
| `m6/` | M6 多轮可靠性任务、修复记录和最终基线 |
| `m7/` | M7 A～E 任务、设计、执行和联合验收记录 |
| `phase-f/` | 已完成的 Phase F F0～F3 实施任务；现场验收仍在活动任务中 |

## 使用规则

- archive 用于追溯为什么作出某项修复或判断，不用于决定今天要执行什么。
- 已接受且仍有效的架构约束保留在 `docs/decisions/`，不会因为实现阶段结束而归档。
- 历史文档可以包含当时真实存在的路径和状态；顶部 archive 提示具有优先级。
- 当前任务不得直接复制历史测试数量。需要复用证据时，明确写为“继承历史基线”并链接具体记录。
- 阶段完成时，把对应 `tasks/` 和 `records/` 文件移动到此处的里程碑目录，并更新本索引。
