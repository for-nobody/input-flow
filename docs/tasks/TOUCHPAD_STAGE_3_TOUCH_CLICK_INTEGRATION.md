# InputFlow · Stage 3：将 Touch Click 作为实验功能接入 Agent 和规则设置

**任务类型**　设计与开发任务卡 · **状态**　已接入，按[实机记录](../records/TOUCHPAD_STAGE_3_TOUCH_CLICK.md)核对验收范围
**用户验收目标**　用户在「设置 → 实验功能」手动开启「触控板支持」后，才会在规则设置看到 Touch Click。启用 Touch Click 后，关闭设置窗口，在记事本或浏览器中，轻触板面任一侧都能左击，原地长触能右击。物理按压、拖选和双指滚动沿用 Windows 行为。按配置的紧急旁路键（默认 F12）能立即阻止尚未发出的点击。

本卡落实[触控板提案第 15 节 Stage 3](../planning/InputFlow-Touchpad-Expansion-Proposal.md) 的配置、启停、回退、恢复和诊断。Stage 3 只交付 Touch Click。演示指针、触控板数字键盘和通用手势映射留给后续任务。

## 1. 先确定两个开关的行为

「触控板支持（实验性）」是功能总开关。「触控点击 / Touch Click」是规则页内的一组固定行为，包含“启用”、短触上限、长触门槛和移动阈值。首次开启总开关仅显示这些选项，用户能先了解原生轻点的影响，再决定启用点击。Stage 3 的短触固定为左键，长触固定为右键。使用一个内置规则区即可，无需让用户手工建立两条规则。

| Agent 已确认的配置或状态 | 规则设置里看到什么 | Agent 的行为 |
|---|---|---|
| 新装、旧配置升级，或总开关关闭 | 设置页保留实验开关。规则页隐藏整个触控板区，包括新增／编辑入口、阈值、Tab 焦点和朗读项 | 两个开关初始均关。总开关关闭时退出触控板订阅，撤销候选、定时器和待发点击 |
| 首次打开总开关，Touch Click 关闭 | 出现 Touch Click 规则区，可编辑参数、启用规则 | 普通使用中不合成点击。开发用只读观察须显式启动 |
| 两个开关均开，设备和运行状态合格 | 显示参数及 Agent 的实际状态 | 从一次新的完整接触开始识别；关闭 Settings 后继续运行 |
| 两个开关均开，但设备不支持、已拔出、Agent 暂停或保护已触发 | 保留可见的规则配置，显示具体原因 | 停发触控点击。其他输入服从原有 Agent 暂停／旁路策略 |
| 已配置后关总开关，再次手动开启 | 关闭时隐藏，重新开启时恢复原来的参数和规则启用值 | 关闭期间零触控板输出。重新启用后重新核对设备、故障和接触状态；开关旁提示会恢复已启用的规则 |

开关和参数都经现有草稿／保存流程生效。标明未应用状态；保存失败、断线或结果待核对时，展示最后确认的配置与实际状态，保留未保存的编辑。隐藏触控板区或只保存一条键盘规则时，触控板设置仍应完整往返。紧急停用沿用旁路键和托盘入口，无需等待设置保存。

## 2. Codex 从这里开始

1. 阅读 [Stage 1B 设备和接触记录](../records/TOUCHPAD_STAGE_1B_PROBE.md)、[Stage 2 实测记录](../records/TOUCHPAD_STAGE_2_TOUCH_CLICK.md)，包括末尾的 F7 专项复测。F7 由探针合成左右键，是首选候选；F6 依赖原生短触，两轮快速双触都出现漏点。F7 的成功样本只涵盖已收到的接触，历史未标记左键和保护停用仍待解释。用户反馈的“碰了但没反应”要作为独立验收场景。F6、F7 只用于描述探针实验。
2. 在当前 checkout 核对下表入口。动手前，在 `docs/records/TOUCHPAD_STAGE_3_TOUCH_CLICK.md` 简记实际基线、选定的消息窗口／线程、两个开关的配置归属、取消与发送如何排序、如何测量漏点。随后实施 3A，并推进可以自动验证的配置、协议、UI 和测试，不用等人工做手势才开始编码。
3. 在独立探针的**同一次连续启用**中补齐缺口。记下 Windows「单指轻点以单击」的实际值，框内物理按放确认目标命中，再测左右侧短触、快速双触、足时长触至抬手、物理按压拖选。记录有无额外左键、重复、保护停用或中断。可复用已有证据，只补缺项。原生点击来源仍冲突或物理按压无法可靠区分时，保留只读路径、继续无输出开发。先补独立原型证据，再向普通应用启用真实点击。

| 先看的仓库入口 | 需要落实的设计 |
|---|---|
| `experiments/touchpad-probe/src/{hid,contact,gesture,output,stage2}.rs` | 复用描述符解码、按设备跟踪、手势状态机及边界测试。让探针和 Agent 使用同一份判定逻辑；保留独立探针的原有运行方式和测试窗口 |
| `crates/inputflow-windows/src/platform/{shell,windows}.rs`、`crates/inputflow-runtime/`、`apps/inputflow-agent/` | 查清托盘窗口和 Hook 线程各自拥有的资源、旁路／录制／配置替换入口及现有输出失败处理。由 Agent 拥有后台订阅，低级 Hook 回调中避免做 HID 解析、磁盘 I/O 或设备查询 |
| `crates/inputflow-config/src/config.rs`、`crates/inputflow-protocol/`、`apps/inputflow-agent/src/ipc.rs` | 定义持久配置与只读运行状态，接入握手能力、校验、热应用和状态读回 |
| `apps/settings-winui/InputFlow.Settings.Core/`、`InputFlow.Settings/MainPage.xaml`（后者相对于 `apps/settings-winui/`） | 复用 `ConfigModels`、`DraftSession`、`ConfigSaveService` 及现有设置页和规则页。当前通用规则的 `ActionConfig` 只支持键盘组合；固定点击行为不需要扩展为可绑定任意动作的规则类型 |

## 3A · 在后台只读识别

- 在 Agent 的消息窗口为触控板顶层集合（usage page `0x0D`、usage `0x05`）统一管理 Raw Input 注册、设备通知和注销。参考探针已有的 `RIDEV_INPUTSINK` / `RIDEV_DEVNOTIFY` 路径。按实际设备描述符取得坐标、接触和按钮能力，分别跟踪设备，忽略不完整或归属不明的接触。型号和报告 ID 不应写死。
- 短触须有明确 UP，时长 **≤ 400 ms** 时产生一次左键意图。**400 < 时长 < 500 ms** 时无点击。有效单指仍在板面时，可取消的单调计时器达到 **500 ms** 即产生一次右键意图。长触后抬起、计时器重复或在 UP 后迟到均不补发。两次短触独立识别，第一下无需等待双击窗口。
- 距起点的全程最大位移首次 **> 3.0 mm** 即取消，折返仍保持取消。缺可靠物理单位时，参考探针按两轴逻辑跨度分别归一化、再取欧氏距离的 **0.025** 候选值，标注单位，先做只读验证。多指、物理按压或失去设备归属时取消；恢复一指后等待全部离开，再从新 DOWN 开始。
- **本段通过条件**　在真实 Windows 宿主机上关闭 Settings，将焦点切到记事本或浏览器，独立观察会话仍收到可归因报告，能区分短触、长触、滑动取消；合成输出计数始终为零。在长触等待中暂停，恢复后旧候选消失。若后台报告为零，先对比同一设备、同一动作的前台探针记录。

## 3B · 接入点击、旁路和恢复

在 3A 和独立原型的点击来源验证通过后，用可观测的目标窗口验证 Agent 的输出，再到普通权限的外部应用测试。Agent 负责带现有自身标记的成对按下／抬起，自己的合成鼠标事件直接旁路规则匹配。只有触控板 HID 接触可以启动这套识别器。

| 事件 | 实现和验收要求 |
|---|---|
| 手势等待期间切换前台或指针目标 | 记住发起手势时的目标，输出前重新核对前台、指针命中目标、当前开关和候选有效性。目标改变则取消，防止右键落到新窗口 |
| 总开关／规则关闭、F12、托盘暂停、开始录制、热应用、退出 | 在同一受控顺序中作废已有接触、计时器及待发输出。测门槛到达与取消同刻、旧计时器晚到、接触 ID 重用。已观察到的取消优先；恢复后须有新 DOWN |
| 锁屏、睡眠、拔出、异常退出后重启 | 清除瞬时状态；解锁、唤醒和重连后重新识别设备。启动时读取持久开关并遵守 Agent 现有恢复／旁路状态。故障解除后才允许新的点击 |
| 原生单指轻点有冲突 | 由用户掌控 Windows 设置。若需要手动关闭原生轻点，说明当前值、入口、影响和恢复方法；关闭实验或 F12 暂停后，物理点击应仍可用，手动关闭的轻点须由用户恢复。外接鼠标和物理点击也可能产生未标记消息，单凭缺少标记不能归因为重复轻点，更不能全局吞左键 |
| 输出为零或部分成功 | 检查实际插入数，停止后续触控点击。对本次已插入的 DOWN 按现有策略做有界释放，记录清理结果，避免整批重试。保留原有全局故障旁路；设备缺失等局部原因只停触控板功能 |

## 3C · 完成配置与 WinUI 验收

- 在同一份正式配置中持久化实验总开关、Touch Click 启用值和参数。当前快照为 schema v4，Rust 使用 `deny_unknown_fields`。若基线仍为 v4，引入 v5，沿用 v1–v4 的内存迁移和显式保存／备份路径，保留原规则、顺序、启停和自定义旁路键。校验两个时长和位移阈值合法、有限、为正，且短触上限小于长触门槛。
- Named Pipe 握手公布 schema 和触控板能力，状态查询区分「已配置」「设备可用」「实际允许输出」及原因。新 Settings 连旧 Agent 时隐藏不可用功能；旧 Settings 连新 Agent 时验证版本保护能阻止有损写回。旧 Agent 打开未来配置时须保护原文件。覆盖保存失败、外部修改、运行时回滚、结果未知后重连读回。
- 按第 1 节的表实现设置页、规则页和显示条件。复用 `en-US`、`zh-CN` 的 `.resw`、键盘导航和自动化名称。实测在规则编辑中关闭实验、保存另一条规则、再打开实验，确认隐藏项不会被重置，也不会残留在焦点或朗读顺序中。关闭／重开 Settings、Agent 正常重启后，检查两处 UI 和实际运行状态一致。

## 验收与交付

| 在哪里测 | 执行方法与合格证据 |
|---|---|
| 自动化测试 | 用可控时钟覆盖短／长触边界、同刻取消、迟到计时器、折返、多指和物理按钮。模拟完整／零／部分插入，验证只释放已发出的按下。覆盖双开关组合、旧版迁移、关闭时保存键鼠规则、配置往返和协议错配。按 [Windows 构建指南](../guides/BUILD_WINDOWS.md) 执行 Rust workspace、WinUI Core／Protocol 和双语检查；独立 probe 另用其 manifest 运行测试 |
| 同一启用会话，真实 Windows 触控板 | 板面左右侧短触各一次左击；快速双触两组按放并在系统条件内形成双击；足时长触在抬手前只出一次右击。检查慢滑、折返、物理左／右按压、拖选、双指滚动及外接鼠标。记录原生行为、额外点击、软件观测延迟与操作者手感。再在关闭 Settings 的外部应用验证单击选中、双击选词、长触打开菜单 |
| 复现“碰了但没反应” | 用独立按键或操作者确认逐次划定试次并记录意图。每次对应设备报告数（含 0）、DOWN/UP 完整性、手势判定／取消原因、请求和实际插入数，以及测试目标收到的消息。双触按“一次尝试、预期两次接触”记账。列出漏点数／实际尝试数、误右键数／无意右击试次数和重复点击数。零报告标记为“本次未观察到”，保留原因未知；不能用已收到的接触数代替实际尝试数 |
| 生命周期和既有规则 | 按第 1 节与 3B 的表逐项验证关开、重启、失焦、故障、旁路和恢复；同时用已有键鼠规则验证物理输入仍可匹配，自身合成事件不再触发规则。普通应用用可见行为验收，精确送达数用测试窗口核对；日志中的“已插入”只说明输出调用的结果 |

日常诊断保留设备状态、报告／完整接触／意图／输出计数和最近取消或停用原因。逐试次诊断限于主动采样时段，避免常驻记录手指轨迹。把实际修改、构建命令、宿主机与设备、原生设置和恢复结果、各项分母、失败样本及未测项写入 Stage 3 记录。依[文档治理规则](../governance/DOCUMENTATION_POLICY.md)更新相关索引和状态。

**完成判据**　从正式入口启用，到关闭 Settings 后在外部应用完成单击、双击、长触、暂停及恢复，整条路径须有同一台宿主机的证据。缺 Windows 实机时，交付已实现的代码、自动测试结果和可直接运行的实机步骤，并将相应项标为「待实测」。同一点击来源下仍有重复点击、拖动干扰或保护停用时，记录能复现问题的最小动作，保留只读结果。本机通过只覆盖记录中的硬件、原生设置与操作范围。
