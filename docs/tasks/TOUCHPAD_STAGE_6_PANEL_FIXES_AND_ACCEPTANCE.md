## 1. 正式保存期间保护画布草稿（高优先级）

**复现顺序**

1. 打开预设 A 的独立画布并移动分界线，暂时保留画布窗口。在主窗口修改另一个可保存的字段，例如预设 B 的名称。
2. 在主窗口点保存。用可控的测试 Agent 或异步测试替身让正式保存停在已取得草稿快照、尚未返回结果的位置。用同步信号控制顺序，避免依赖人工抢点或固定延时。
3. 在 A 的画布点「保存到草稿」，然后让第一次正式保存成功返回。检查画布是否关闭、A 的分界线是否仍在、主窗口的草稿状态以及 Agent 和磁盘中分别保存了哪一版。

**排查入口**　`MainPage.xaml.cs` 的 `SaveDraftAsync`、`MainPage.Panel.cs` 的 `SavePanelCanvas`、`PanelCanvasWindow.cs` 的 `TrySave`，以及 Settings Core 的 `ConfigSaveService.SaveAsync`、`DraftSession.AcceptSaved`。当前代码先冻结主草稿，成功后使用正式读回值重载草稿。检查这两个时刻之间进入的画布写回。

**修复与通过条件**　优先复用主窗口的保存状态。在正式保存期间暂缓画布写回，画布保留编辑和撤销历史，并告知用户何时可以重试。写回保护放在公共提交入口，同时覆盖左上角按钮和关窗对话框的「保存到草稿」。

- 第一次正式保存成功后，B 的改名已应用，A 的新边界仍保留在画布。此时 A 可保存到主草稿并自动关窗，小图更新、主草稿显示待保存。第二次正式保存后，重开能读到 A 的新边界和 B 的新名称。
- 第一次正式保存失败时，画布仍可继续编辑或重试。任一路径均不得报告画布保存成功后又静默丢弃编辑。保留已有的预设 ID、目标已删除和几何冲突检查。

## 2. 拖动中按 Delete，只删除一次（高优先级）

在选择工具下，从已有绑定的区域内部按住鼠标左键，移动到出现拖动预览，保持按住，按 `Delete`，再移动并松开。检查 `PanelCanvasWindow.cs` 中 `DeleteSelected`、`CancelDrag`、`UpdateDrag` 和 `Released` 的顺序。删除后残留的拖动会携带旧 ID，几何层 `PanelGeometryEditor.MoveRegion` 随后的 `Single(...)` 查找可能抛出异常。

让键盘、工具栏和区域菜单共用的删除入口先结束拖动、清理预览与指针捕获，再对选区提交一次删除。验证后续移动、松开和捕获丢失事件均可安全结束。验收时检查窗口继续响应、源区域消失、松手处没有新区域。一次 `Ctrl+Z` 恢复删除前的原始轮廓、名称和绑定，`Ctrl+Y` 再次删除。文本框与快捷键录制仍按各自语义处理 Delete。

## 3. 支持独立矩形的四条外边拖动

用矩形工具在空白板面中央画一个矩形，绑定 A，切回选择工具，从右边缘中点向右拖。现实现的 `FindEdge` 只查询两个区域之间的公共边。请在 `PanelCanvasWindow.cs`、`PanelBoard.cs`、`InputFlow.Settings.Core/PanelGeometryEditor.cs` 中接通独立轴对齐矩形面向背景的边缘命中、预览和提交，复用现有几何校验及历史。

| 用户操作 | 通过条件 |
| --- | --- |
| 分别从左、右、上、下边中点拖动 | 悬停可辨认缩放方向，拖动时显示最终轮廓。只有所拖边沿垂直于边的方向移动，对边固定。区域 ID、名称、动作和绑定保留。 |
| 从矩形内部拖到右侧空白 | 整体按抓取点平移，形状和大小保持，原位释放，周围继续留白。从已有公共边拖动仍同步调整相邻两侧。 |
| 缩放越界、跨过对边、压成零面积或与其他区域重叠 | 给出无效反馈，松手保留上一次有效布局。Esc 可取消预览。无效操作和取消都保留撤销／恢复历史。 |
| 正常缩放后撤销、恢复、两级保存并重开 | 一次拖动只占一步。主窗口小图、重开后的编辑器和正式几何一致。 |

给几何测试加入确定坐标的例子：矩形从 `(0.20, 0.25)–(0.45, 0.65)` 拖右边至 `x=0.60`。点 `(0.52, 0.45)` 由背景变为 A，左边仍在 `x=0.20`，撤销后该点重新属于背景。补测其余三条边，并运行已有的「交换已绑定区域、填入未绑定分区、平移到背景」测试。

## 4. 在实体触控板上复核一次轻触只输出一次（G1）

此前移动斜边后的人工结果为 `aba`，中途被动读回出现过 `abaa`。历史累计数包含同一会话内的其他接触。用相同 Release 构建和隔离配置做三次可单独归因的试次。

1. 打开对角线 A/B 布局，在记事本使用英文输入。选取远离边界窄缝的 A 内部点和 B 内部点，记录 B 点的定位方式。Settings 关闭后，分别对两个点各轻触一次，每次独立取样。
2. 重新打开画布并移动公共斜边，让原 B 点进入 A。先保存到草稿，再由主窗口正式保存，关闭 Settings。重新进入面板，在原 B 点只轻触一次。
3. 每次触碰前后，被动读取同一记事本文本及同一 Agent 会话的状态。采样和模式切换安排在触碰区间之外，取数时保持记事本焦点。记下设备、布局版本或配置哈希、点位、目标文本前后值和三个计数增量。

| 每次独立试次 | 文本新增 | confirmed | requested_inputs | inserted_inputs |
| --- | --- | ---: | ---: | ---: |
| 原 A 点 | `a` | +1 | +2 | +2 |
| 原 B 点 | `b` | +1 | +2 | +2 |
| 移边后的原 B 点 | `a` | +1 | +2 | +2 |

表中两个输入事件对应单个字母的一次按下和一次释放。若再次出现额外字符，保留异常试次，沿触点 ID 与明确抬手、识别确认、排队与注入、目标文本逐层定位。只有证据指向具体路径时才修改识别或输出逻辑。

## 5. 在 Num Lock 开、关两种状态下复验数字和四则运算（O1）

沿用 Stage 6 数字动作的顶排扫描码设计。没有实体 Num Lock 键的笔记本可在每组开始前使用 Windows 屏幕键盘设定初始状态，再将焦点交回目标应用。面板的进入、切层、输出和退出均应保留这组的初始状态。记录目标应用、键盘布局和 Num Lock 前后值。

| 目标 | 两种状态下各执行一次 | 通过条件 |
| --- | --- | --- |
| 记事本 | 分别输入 `2468`、`505`、`55` | 文本逐字符相符，重复数字均被保留。 |
| Windows 计算器，标准模式 | 每次清零，分别输入以上三串数字。再分四次输入 `8+2`、`8−2`、`8×2`、`8÷2`，每式点面板 Enter | 数字进入显示框，2/4/6/8 不移动焦点。四式结果依次为 10、6、16、4。 |
| 电子表格 | 选定单元格，用面板输入 2 并点 Enter | 单元格保存数值 2，提交一次。 |

若目标应用失败，记录实际按键、焦点与界面结果，分别检查数字、运算符和 Enter 的输出路径。继续保留普通重映射规则中显式指定的真实小键盘键语义。
