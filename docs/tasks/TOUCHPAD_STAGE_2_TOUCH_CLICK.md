# InputFlow · Stage 2：Touch Click 实验原型

建议位置为 `docs/tasks/TOUCHPAD_STAGE_2_TOUCH_CLICK.md`。任务状态为待执行。对应触控板提案第 3 节、第 15 节 Stage 2，以及第 18 节 Experiment A。

**目标**　在同一块触控板的左侧和右侧，手指短触抬起都能产生一次左键；单指原地长触能在抬起前产生一次右键；移动光标、滚动或拖动时能照常操作。交付一个可在 Windows 宿主机运行的独立前台原型，以及一次有实际点击结果的实机记录。正式 Agent、WinUI、配置 schema 和发布包的集成属于 Stage 3。

## 从现有探针开始

先读 `docs/planning/InputFlow-Touchpad-Expansion-Proposal.md`、1A 和 1B 的实机记录，再阅读当前工作树里的 `experiments/touchpad-probe/`。复用该探针的设备归因、HID 描述符解析、单指生命周期和现有采样模式。运行环境及启动方式以宿主机 checkout 的 README 为准。

- 1B 已在 ASUS Zenbook 14 UX3405MA、Windows build `26200.9974`、ASUS `093A:300D` 上完成前台解码。19 个采样段内 21 次接触均有配对 DOWN/UP。7 次短触为 91～316 ms，7 次静止长触为 736～1163 ms。
- 慢滑组有 5 次向右滑动和 2 次主动向左回位。操作者已确认左移是为避免指针碰到屏幕边缘。这两次可作为反方向的正常移动样本，无需重跑 1B。
- 1B 坐标为触控板表面逻辑单位，X 为 0～3996、Y 为 0～2242。原记录只列起止坐标。另采少量带**全程最大偏移**的动作即可校准移动阈值。1B 报告 ID 和逻辑范围只描述这台设备，继续使用运行时取得的描述符。

## 2A · 先让识别结果可见

在原探针增加只读识别模式，窗口显示本次接触的判定、判定时刻与原因。建议从短触上限 **400 ms**、长触门槛 **500 ms** 开始，两者均可在本次实验调整。约定短触上限包含等号，400～500 ms 之间的开区间暂不点击。这个区间是可验证的实验选择，尤其要记录用户有意轻点却落入其中的次数。

| 事件 | 本次接触应如何处理 |
|---|---|
| 有效单指 DOWN | 记下设备、接触 ID、起点和单调时间，创建本次候选。已抬起的 ID 可以复用。 |
| 在短触上限内明确 UP，且资格仍有效 | 输出一次短触意图。两次独立短触分别判定，第一下无需等待第二下。 |
| 长触门槛到达，单指仍按住、未越界、资格仍有效 | 当场输出一次长触意图；继续停留或稍后 UP 均不再点击。使用可取消的单调计时，不依赖下一份移动报告触发。 |
| 手指距起点的距离首次超过阈值 | 永久取消本次尚未触发的点击；滑回起点、停住超过 500 ms 仍保持取消。指针移动继续由 Windows 处理。 |
| 达不到短触条件即抬起，长触也尚未触发 | 标记原因并结束。若定时器滞后到已经处理 UP 才执行，记录迟到，不能在抬起后补发右键。 |
| 多指出现、物理按钮按下、前台目标丢失、设备移除或停止实验 | 取消待触发候选及其计时器。中断后从一次干净的新接触重新开始。多指退回一指、旧计时器迟到及接触 ID 重用都不能意外启动旧动作。 |

优先处理已经观察到的抬起、越界和中断，再决定到期的长触。用可控制时钟的测试覆盖门槛前后、同刻取消、连续两次短触、重复定时事件和 ID 重用。若右键已在门槛触发，此后才出现的移动或物理按压不能撤回先前的右键；将这种顺序单独记为可用性案例。

**位移校准。** 对每次有效报告更新“距起点的最大距离”，同时保留最终净位移和首次越界时刻。优先用描述符可可靠换算的毫米；否则用明确定义的归一化坐标，并记录 X/Y 换算方法。例如用各轴逻辑跨度归一化时，要明确所得单位是轴跨度比例。先各采几次自然轻点、轻微抖动的长触、故意慢滑与折返，选一个能容纳自然抖动、又能在滑动时及时取消的实验值。记录单位、选值依据和出现重叠的样本。用另一组动作复验，避免用同一批动作既定阈值又宣告通过。

## 2B · 在测试窗口里验证真实点击

完成 2A 的现场检查后，继续实现显式开启的点击输出模式。默认启动只观察。用同一前台窗口的专用测试区接收点击、显示计数，并提供停止输出或 Esc 退出。启用前、输出前核对前台目标和指针位于测试区，离开或失焦时撤销待处理动作。仅用一个前台窗口就能完成本阶段；后台订阅的结果另记。

1. **先测 Windows 原生行为。** 保持合成输出关闭，在同一测试区执行短触、长触后抬起、快速双触和物理按压。记录 Windows 原本送达了哪些左/右键消息，尤其关注长触后抬起是否仍收到原生左键。检查探针是否能可靠识别物理按压，比如设备描述符中的 Button 用途；先用实际按压核实。
2. **每个手势选定一个点击来源。** 若原生轻点已产生左键，可让 Windows 负责短触，探针只补长触右键；实测确认长触周期从按下直到抬起合计仅一次右键、零次左键，再判定此组合可用。若无法避免重复，改测由探针负责两种点击的方案。需要关闭 Windows 原生单指轻点时，将原值、设置入口和恢复方式交代给操作者，由其显式手动切换，结束和异常中断后均可手工恢复。若保持原设置且冲突仍存在，保留该模式的失败结果。实验工具本身不持久更改系统设置。
3. **验证实际送达。** 如采用 `SendInput`，使用成对的鼠标按下/抬起，检查实际插入数；部分成功时停用输出，按已发送的按键状态作有界释放处理，记录结果，避免整批重发造成重复点击。识别器只接收已归因的触控板 HID 接触，测试区的鼠标消息用于核对结果，不作为新的触发源。每次实验至少分别记录“意图”“合成输入结果”“目标窗口收到的按钮消息”。[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)
4. **保留双击和拖动。** 用支持双击消息的测试窗口按系统语义统计。连续两次短触应产生两组按放，在系统双击条件内目标可识别一次双击；双击消息可以替代第二次普通按下。用能选中文字或拖动对象的测试区验证物理按住拖动，按压期间抑制 Touch Click 自己的动作。若当前硬件无法可靠区分物理按压，保留只读或已验证的受限模式，记录此项局限。[Windows 双击消息](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-lbuttondblclk)

## 实机验收

先做一遍原生基线，再在明确记录的参数和点击来源下复验。常规动作建议每项先做 5 次，容易误触的动作混合再做一轮；保留实际分母和错判，不以建议次数代替实测。操作者只需要执行物理手势、说明原意及反馈手感。其余编译、分组、计数和汇总由 Codex 完成。

| 操作 | 观察结果 |
|---|---|
| 分别在板面左、右侧短触抬起 | 每次恰好一次左键，零右键。记录有意短触却未触发的次数。 |
| 静止长触、带少许自然抖动的长触 | 抬手前只出现一次右键；持续停留和抬起后无额外点击。 |
| 慢滑、快滑、纵向滑、折返、滑动后停住 | 越界后只移动。折返接近起点、移动后停住超过长触门槛，仍为零点击。主动回位计作移动。 |
| 单触与快速双触交替 | 单触不会变成双击，双触送达两组按放。记录短触抬起到目标收到点击的时间。 |
| 物理左/右按压、按住拖动选择、双指滚动、一指变两指再回到一指 | 原生按钮、选区和滚动与基线一致；记录是否出现额外左右键、拖动中断或残留按下。 |
| 长触门槛前移出测试区、失焦、停止后重新启用 | 旧候选不在新窗口或新会话产生点击。 |
| 原生轻点设置复原、退出原型 | 确认普通移动、原生轻点、物理点击和双指滚动恢复为实验前行为。 |

用“**未打算右击却收到右击的次数 / 未打算右击的试次**”呈现误右键率，另列漏点、重复点击及意图/送达不一致。延迟分别记录短触 UP 到目标按钮消息，以及长触门槛到目标按钮消息的观测时间；这些是软件观测值。补一句操作者的实际体验，包括右击等待是否自然、为了避免误触是否需要刻意改变手势，以及板面右侧轻点是否解决最初的不便。
