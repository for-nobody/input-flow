## 0. 本轮目标

基于完成 Phase F 的固定代码，生成普通 Windows x64 用户可以运行、配置、暂停、退出、更新和移除的首个公开测试版本。用户已确定版本 `v0.9.0`、项目许可证 MIT，发布平台标记 Pre-release；Agent／UI／包版本必须保持一致，不能只改发布页。

阶段顺序：G-PRE → H → RC → 发布准备／授权范围内发布。发布后的 G-POST 不在本文件的进入／完成条件中。

进入本任务时必须从当前状态和 Phase F 归档记录读取实际基线。干净机安装、依赖、升级、卸载、签名和最终包只有产生本阶段证据后才能标记完成。

## 1. 通用执行要求

先读取实际 `AGENTS.md`、Git 状态、发布路线、F 的最新执行记录和当前代码。保存用户未提交改动；有更晚基线时更新文档引用，不机械套用历史 HEAD 或测试数量。

每段先写明确问题与最小方案，然后实现和验证。出现阻断缺陷先复现、提出原因假设、修复并增加必要的行为测试；不趁收尾大规模重构已通过的架构，不加 URL／启动程序／序列／层等新功能。

普通本地构建、可逆文件修改和隔离验收持续推进。远端 tag／release、消息发送、签名身份及许可证采用只在用户对应授权下执行；先完成可审阅产物，不因这些待决定事项停下其他工作。

## 2. G-PRE：发布前短时可靠性与异常恢复

这是有限验收，不是 24／72 小时 soak。已有同提交、同产物可信证据可复用；改动后涉及路径需要新结果。

### G1. 自动回归

运行现有 `scripts/build-windows.ps1` 和必要定向检查。至少包含 fmt、Rust workspace、Clippy `-D warnings`、probe／Agent Release、WinUI Debug／Release、protocol／Settings Core、真实 Agent contract（有目标 Windows 时）。记录完整命令、环境、退出码、测试数量；测试失败不继续生成“成功”发布包。

检查新方向规则对旧配置、四类触发器、tombstone、repeat／16 项溢出、SendInput 零／部分／完整、timer、owner 串行化、原子保存和备份优先级的影响。

### G2. 有限实机矩阵

| 编号 | 场景／建议次数 | 必须观察 |
|---|---|---|
| PRE-01 | 一次约 10～15 分钟混合打字、快捷键、菜单、拖拽与方向手势 | 真实输入持续可见；无丢键／粘键／无故旁路，资源／延迟有记录 |
| PRE-02 | UI 打开／关闭约 20 次 | UI 进程完全退出，Agent PID 持续；句柄／线程无每次增加趋势 |
| PRE-03 | 约 10 次启停／编辑／保存，包括方向候选中替换 | runtime／磁盘 settled；其他规则不被误禁用；旧候选不延续 |
| PRE-04 | 设置进程异常结束／重开、Pipe 断线／重连各一次 | Agent 不依赖 UI；读回权威状态；迟到 capture 不覆盖字段 |
| PRE-05 | Agent 正常退出／重启；另在隔离数据目录做异常终止恢复 | marker／配置恢复信息真实；不残留旧 candidate／实例锁 |
| PRE-06 | F12／UI／托盘暂停恢复，包含方向键按住／候选中 | 单一权威状态；释放归属正确；暂停期间 move 直通 |
| PRE-07 | 锁屏解锁／可用时一次睡眠唤醒 | 无过期候选命中；恢复后实际输入和规则仍工作 |
| PRE-08 | 普通目标输出，必要时回归提升目标的 UIPI 边界 | 完整／零插入判定准确；不把预期拒绝当作成功 |
| PRE-09 | 所涉及 M6 release／退出边界 | 无新增孤立 Up；两秒 drain 上限及强杀限制保留 |

不要重复破坏真实用户配置制造故障；坏文件／回滚测试使用隔离目录。强制结束只能针对已核对路径与 PID 的测试实例，记录该操作以及不可恢复的暂扣历史输入限制。

缺少睡眠、多屏或特殊键硬件时记录环境限制，并完成可用平台观察和确定性边界。已发现的真实恢复缺陷不能以“长测以后再说”跳过。

资源线沿用 F 短测参考，报告样本数、分位与 max、CPU 差分口径、private／working set、线程／句柄。不能只凭 PID、ready 或 IPC 能回复断言 Hook 未丢失；需要真实输入观察或目标消息。

### G3. G-PRE 通过标准

自动门槛通过，矩阵中可用环境完成且关键输入／保存／恢复无阻断缺陷。deliberate UIPI 拒绝、故障注入和主动暂停应与普通输入错误计数分开，不能为了凑“0 错误”删掉这些证据。

通过后进入 H；**无需 24／72 小时长测、几天自用或连续数小时等待。**

## 3. H：可分发产物与生命周期

### H0. 做一次有限部署选择

写 `docs/decisions/ADR-009-首版分发与用户生命周期.md`（编号被占用时使用下一空闲号）。比较现有 unpackaged、self-contained 与 framework-dependent，以及可选用户级安装器；说明体积、依赖、安装权限、更新／移除和兼容范围。

**首版默认优先：unpackaged x64 便携目录包，Agent 保持纯 Rust，设置程序优先验证 .NET 与 Windows App SDK 各自的 self-contained 发布。** 这是待验证的交付建议，不是目前工程已具备的配置。若当前锁定版本无法可靠实现，记录证据后使用明确依赖安装步骤的 framework-dependent 方案；不要为了赶发布升级整套 SDK 或改变架构。

MSIX、商店、商业签名和自动更新不是首版必需条件；独立 installer 可后续增加。首版仍必须有实际可用的首次运行、可选自启动、升级和移除流程。用户若指定安装器，则在现有方案上实现，不把便携默认当成覆盖用户要求的理由。

### H1. 发布构建和依赖

- 新增有限的 `scripts/package-release.ps1` 或等价统一入口，先调用已验证的构建门槛，再发布 UI／拷贝 Agent／整理附件／生成校验和；任一步失败返回非零。
- .NET 的 `SelfContained` 与 `WindowsAppSDKSelfContained` 是两个独立维度；不要只打开一个就声称干净机无需运行库。
- `dotnet publish` 针对具体 UI 项目／发布 profile；不要把此前已失败的 solution `-r`／Platform 组合重新当作有效命令。
- 首版优先目录发布，避免新增单文件、AOT 或裁剪优化的风险；当前 Release 工程有 `PublishTrimmed=true`，发布前明确验证，默认可在 release profile 关闭裁剪，保存理由，不照搬开发构建属性。
- 使用锁定依赖和真实版本；不在打包过程中下载未知“最新版”。不把开发机 SDK 或绝对路径作为运行前提。
- 核对 Rust MSVC／原生 DLL 的实际目标机依赖，不能因 Agent 是 Rust 就假定只有一个 EXE 一定可运行。
- 决定实际支持的 Windows x64 版本；最低 TFM／manifest 只是声明，发布说明以真实目标环境为准。

具体 publish 参数由实际 SDK 官方文档和测试决定，写入 BUILD_WINDOWS；不要把本文的候选属性当作已执行命令。

### H2. 产物布局与启动

基线 Agent 会从自身目录查找 `InputFlow.Settings.exe`，也接受 `--settings PATH`。选择同目录发布，或在 layout／启动入口中明确传递准确路径；不得分开复制两个 exe 后让托盘 Open Settings 失效。

默认用户配置继续位于现有 `%LOCALAPPDATA%\InputFlow` 数据目录；配置／日志不能要求写程序目录或 Program Files。首次启动无已启用演示规则，避免改变用户正常输入；导入示例需显式启用。

验证：解压到任意路径、路径有空格／中文、工作目录不是程序目录、从快捷方式／托盘启动、设置单实例和 Agent 单实例。不依赖开发机目录，也不偷偷安装第二套 Hook。默认启动 Agent；设置程序按需打开，不随登录常驻。

### H3. 可选登录自启动

- 默认关闭；只针对当前用户 Agent，使用一种透明、可移除的方法，例如当前用户 Startup 快捷方式。先设计后实现，不默认加高权限任务或服务。
- 首版可以通过设置页真实控制，或提供明确的 enable／disable 脚本与说明；不能放假开关。显示状态来自实际系统配置，不只读本地布尔值。
- 路径与参数正确引用，工作目录明确；重复启用不产生重复入口；禁用只删除 InputFlow 自己拥有的入口。
- UI 关闭不影响 Agent，登录时不启动 WinUI；重登录／重启后验证一次真实启动及单实例。
- 升级或移动安装目录时明确更新入口；目标路径不存在时可诊断，不产生无限启动循环。
- 不自动重启／注销用户桌面来完成测试；相关真实操作由用户协调，其他任务继续。

### H4. 升级与移除

便携包升级：正常退出旧 Agent → 保留数据目录及有效备份 → 切换完整程序目录 → 必要时更新自启动入口 → 启动新版本 → 核对配置及方向规则。不得在运行中逐个覆盖 DLL／exe。

Schema 升级要有迁移与降级说明。旧 Agent／UI 不支持新 Schema 时明确拒绝；不能由旧版静默回滚破坏新方向规则。准备至少一个真实旧版或经记录的迁移模拟来源；模拟不能标为真实二进制升级。

移除：关闭 UI／正常退出 Agent → 禁用自启动 → 删除已确认的程序目录。默认保留用户配置，用户可按说明选择删除专属数据目录；不删除共享 .NET／Windows App Runtime，不影响其他软件。若使用 installer，卸载流程也满足这些要求。

### H5. 干净环境验收

在没有 Rust、Visual Studio、.NET SDK 或开发仓库的 VM／第二台设备／受控干净用户环境验证最终包。若声称 self-contained，测试机不预装对应可依赖运行库，或明确证明用了包内组件。已装有 runtime 的“新用户”不能证明 runtime-free。

| 编号 | 最低覆盖 |
|---|---|
| DIST-01 | 下载／解压／启动，无开发工具；Agent ready、托盘和 UI 正常 |
| DIST-02 | 创建并保存四方向规则，真实命中；关闭／重开 UI 读回 |
| DIST-03 | 空格／中文路径、任意工作目录、重复启动与托盘 Open Settings |
| DIST-04 | 启用／禁用自启动、一次重登录或重启观察，仅 Agent 常驻 |
| DIST-05 | 升级保留配置与禁用状态；未知新 Schema／降级拒绝 |
| DIST-06 | 正常退出、移除自启动和程序；默认保留配置，无进程残留 |
| DIST-07 | 缺依赖或错误架构时有可理解说明；不要求关掉系统保护 |

干净环境拿不到时仍可完成全部包和文档，但“分发已验收”保持未完成，不能用开发机成功冒充。目标支持范围可按已验证环境缩小，不臆造兼容性。

## 4. RC：固定最终包的有限检查

1. 冻结本版新功能，只处理发布阻断缺陷；记录实际提交和是否有未提交构建输入，不自动丢弃用户改动。
2. 同步 Agent／UI／package／manifest／关于页／发布说明版本；SemVer、assembly 数字版本与包名的映射有记录。
3. 从固定代码通过统一入口生成包；记录依赖、工具链、命令、退出码、包大小及 SHA-256。
4. 用**这个最终包**做启动 → 四方向配置／命中 → 失败／取消 → F12 暂停恢复 → UI 关闭 → Agent 退出的 smoke；不只测 Debug 工程产物。
5. 此后有源码、依赖、profile 或布局变化，重建包并重复受影响检查；无变化不反复跑同一完整链。
6. 整理第三方许可／NOTICE 和项目许可证。不要替用户凭空选择开源许可证、版权身份或声称已有签名。
7. 包中不放 token、用户正式配置、完整输入日志、坐标轨迹、私有路径、target 缓存或开发测试输出。调试符号按独立附件规划。

准备发布附件：最终二进制包、SHA256SUMS、版本对应更新说明、用户操作文档和支持范围。普通用户不需要阅读 internal ADR 才能首次运行。

## 5. 用户文档与发布页

更新根 README、当前状态、构建指南和必要参考文档，新增版本对应的 CHANGELOG／release notes 和用户指南。不要重新创建重复项目规划或跨阶段记录。至少说明：

- 下载哪个 x64 包，依赖是否随包／如何安装，首次启动顺序和默认不拦截。
- 创建一条方向规则的例子，距离／时间／容差单位；鼠标光标仍移动、按住周期一次触发。
- F12／托盘暂停、关闭设置与退出 Agent 的区别，自启动启用／禁用、升级和移除。
- 配置／日志位置、恢复与反馈所需版本／规则／手势／环境；默认不采集逐键内容。
- UIPI、当前修饰状态、焦点、强杀与两秒退出边界，硬件／语音环境未验证项。
- **本版未完成 24／72 小时长时间运行验收，后续 G-POST 会补充；首版为公开测试版本。**

不把“feature-complete”“151 tests”或“开发机可启动”写成已证明长期稳定。

## 6. 发布动作与授权

准备 release 标题、正文、标签命名、附件、精确 commit、校验和和本地可执行发布命令。版本号／许可证／签名等必要用户决定汇总为少量具体选择，其余实施继续完成。

若已有用户对远端发布的明确授权，在对应范围使用其指定仓库和工具发布，标记 Pre-release；没有对应授权时停在可审阅发布产物与草稿，告知只差哪项实际发布动作。不要推送未经要求的 tag、分支、release 或给他人发消息。当前文档编写请求本身不等于远端发布授权。

发布成功后核对 release 指向正确提交、附件名／校验和、下载可用和 Pre-release 状态；不需要再把整个源项目压缩发给用户。
