# InputFlow 首版 Release 路线

> 日期：2026-10-02（Australia/Brisbane）  
> 状态：已确定的规划；Phase F、发布前收尾和发布后长测尚未执行。  
> 范围权威：用户已确定首版包含鼠标方向，长时间运行测试在首版发布后。

## 1. 当前基线

按 `M7-Phase-E与M6-Windows实机验收记录.md`：M6 Windows 矩阵与 M7 Phase A–E 已完成；最终自动记录为 Rust 151／151、C# protocol 6／6、Settings Core 11／11，WinUI Debug／Release 构建通过。Release 五分钟负载的 stats RTT p99 为 16.032 ms，callback p99 为 328 µs，output failed／dropped 增量为 0。

这些是已记录的单机基线。新代码和最终分发包需要新的验证，不能把旧数字作为未来提交的结果。keypad Enter、独立播放键、中文 Narrator 语音和 partial SendInput 的未实测边界继续保留。

## 2. 阶段及执行顺序

| 顺序 | 阶段 | 交付 | 是否阻塞首版 |
|---|---|---|---|
| 1 | F／M8 | 有激活条件的鼠标四方向、算法、版本化配置、现有 WinUI 编辑／预览、短时高频实测 | 是 |
| 2 | G-PRE | 新代码自动回归、短时混合输入、开关／断线／恢复／退出等关键异常边界 | 是 |
| 3 | H | 可分发 x64 包、运行依赖、路径解析、可选登录自启动、升级与移除、干净环境验收、用户文档 | 是 |
| 4 | RC | 对固定提交和最终包做一次有限发布检查；整理版本、校验和、限制及发布草稿 | 是；没有长测等待条件 |
| 5 | 首个 Release | 首版公开测试版本；建议 `v0.9.0-beta.1` 并标记 Pre-release | 本轮目标 |
| 6 | G-POST | 同一版本的 24／72 小时长测、长期 daily-drive、资源趋势和异常状态加固 | 否，发布后执行 |
| 7 | 后续版本 | 根据长测与试用反馈修复，发布 v0.9.x；条件具备后再承诺 v1.0 稳定行为 | 后续目标 |

**Phase G 拆分的是执行时间，不是取消可靠性工作。** 发布前处理已经发现的阻断缺陷；发布后的长测用于补充长时间证据。RC 仅表示候选产物已准备好，不要求先自用几天，也不要求完成 24／72 小时采样。

## 3. 首版功能冻结边界

首版必须包含：已有四类触发器、完整键身份、规则启停、配置事务与恢复、Win32 Agent／托盘、版本化 IPC、WinUI 设置，以及 Phase F 的键盘激活鼠标四方向。

首版动作继续使用已有键盘组合输出。URL、启动程序、按应用规则、序列／层、设备区分、触控板原生手势、云同步和插件不属于本轮实现范围。鼠标按钮激活不是四方向交付的必需条件；Phase F 先完成键盘激活，按钮激活留作独立评估。

首版支持范围先限 Windows x64；实际 OS 版本支持承诺只能依据目标机测试，不能把项目文件的最低版本当作已验收范围。x86／ARM64 不阻塞首版。

## 4. 发布前有限验证

- F 的确定性算法／状态机测试和跨语言配置 contract。
- F 完成后的真实手势、普通打字／菜单／拖拽和一次不少于五分钟的高频物理移动采样。
- G-PRE 的一次约十至十五分钟混合输入，以及有限次数的 UI 开关、配置应用、断线恢复和进程退出验证。
- H 的干净环境运行、路径含空格或中文、默认配置位置、升级保留规则、停用自启动与移除验证。
- RC 对最终包重复启动、方向命中、失败／取消、暂停和正常退出的发布 smoke。

分段短测无需串成连续数小时；已有可信且版本一致的证据可复用。物理高频鼠标或多屏硬件不存在时，分别保留确定性压力／负坐标测试和真实可用硬件观察，注明未实测能力，不伪造具体 1000 Hz 或跨屏证明。

## 5. 发布门槛与可保留限制

阻断首版：鼠标方向尚未完成；常规使用可复现丢键／粘键／死锁／孤立 Up；紧急旁路失效；保存或迁移损坏配置；最终包在承诺的干净环境无法运行；升级后无法恢复；自启动或移除无法按说明控制。

可公开记录而不自动阻断首版：未做 24／72 小时长测、硬件不存在的键位、部分插入无法稳定实机触发、中文 Narrator 语音环境不足、未测试架构、未签名和未选择 MSIX。已知限制必须准确说明；未签名交付不能要求关闭 Defender 或其他系统保护。

不为满足“稳定”字样设置额外等待时间。首版说明必须注明长测尚未完成，不能宣称已证明全天候稳定。v1.0 以后再讨论长期资源证据、兼容范围和 Schema 稳定承诺。

## 7. 开发记录规则

每段记录实际 HEAD／工作区、方案及理由、修改文件、命令及退出结果、环境、证据路径、限制和下一步。状态使用：未开始／进行中／完成／环境受限／阻断；长测额外使用“计划于首版发布后执行”。

版本号与测试数量必须读取实际产物；正式标签、签名、发布页和下载附件准备完成后，由已有授权决定是否执行远端发布。缺少远端权限时交付本地发布包、说明及待执行命令，不把“发布准备完成”写成“已发布”。
