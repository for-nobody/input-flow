# InputFlow 首版 Release 路线

> 文档类型：稳定发布路线
>
> 范围决定：首版包含鼠标方向；24／72 小时长测在首版发布后
>
> 当前进度：[`../status/CURRENT_STATUS.md`](../status/CURRENT_STATUS.md)

## 1. 阶段顺序

| 顺序 | 阶段 | 交付 | 是否阻塞首版 |
|---|---|---|---|
| 1 | F／M8 | 键盘激活的鼠标四方向、Schema、现有 WinUI 编辑／预览和短时真实输入验收 | 是 |
| 2 | G-PRE | 自动回归、短时混合输入和关键异常恢复 | 是 |
| 3 | H | x64 分发、运行依赖、路径、自启动、升级／移除和干净环境验收 | 是 |
| 4 | RC | 固定最终提交和包，完成有限 smoke、版本、许可、说明和校验和 | 是；无长测等待条件 |
| 5 | 首个 release | 公开测试版本，建议 `v0.9.0-beta.1` Pre-release | 本轮目标 |
| 6 | G-POST | 同一已发布版本的 24／72 小时长测、daily-drive 和资源／恢复加固 | 否，发布后执行 |
| 7 | 后续版本 | 根据长测和用户反馈发布 v0.9.x；有足够证据后再讨论 v1.0 | 后续目标 |

Phase G 的拆分只改变长测时间，不取消可靠性要求。发布前发现的真实丢键、粘键、死锁、紧急
旁路失效或配置损坏必须修复；发布后的长测补充长期证据。

## 2. 首版功能冻结边界

首版包含：

- 已有四类触发器、完整键身份、规则启停、配置事务与恢复；
- Rust/Win32 Agent、托盘、版本化 Named Pipe 和 WinUI 设置；
- Phase F 的键盘激活鼠标上／下／左／右；
- 现有 KeyChord 动作和 Windows x64 分发流程。

本轮不包含 URL／启动程序动作、按应用规则、序列／层、设备区分、无激活鼠标手势、原生触控板、
云同步或插件。鼠标按钮激活也不属于四方向首版门槛。

实际 OS 支持范围只能依据干净目标环境测试。x86／ARM64、MSIX、独立 installer、商业签名和商店
不自动阻塞首版，但实际声明的 x64 分发方式必须可运行、可升级且可移除。

## 3. 发布前验证

### Phase F

- 确定性算法、状态机和跨语言配置 contract。
- 真实四方向、取消、普通输入／菜单／拖拽和约五分钟物理移动。
- 现场资源、Hook 工作证据及受影响 M6/Phase E 路径。

完成证据：[`../archive/phase-f/PHASE_F.md`](../archive/phase-f/PHASE_F.md)。

### G-PRE、H 和 RC

- 一次约 10～15 分钟混合输入，以及有限 UI 开关、配置应用、断线恢复和进程退出。
- 最终分发在空格／中文路径、任意工作目录和声明的干净环境中运行。
- 自启动默认关闭且可启停；升级保留配置；移除不破坏共享运行库。
- 对最终包重复执行方向、失败／取消、暂停和正常退出 smoke。

执行入口：[`../tasks/FIRST_RELEASE.md`](../tasks/FIRST_RELEASE.md)。

分段短测不必串成连续数小时。没有特定硬件时，保留自动证据和真实可用硬件观察，明确未验证范围，
不得伪造 1000 Hz、跨屏或特殊键物理结果。

## 4. 发布门槛

以下任一情况阻断首版：

- Phase F 现场验收未完成；
- 常规使用可复现丢键、粘键、死锁、孤立 Up 或紧急旁路失效；
- 保存、迁移或恢复会损坏配置；
- 最终包在声明环境无法运行；
- 升级、自启动或移除无法按文档控制；
- 版本、许可、发布说明、校验和或附件与最终提交不一致。

以下限制可以准确公开而不自动阻断首版：24／72 小时长测未完成、缺少特殊键或多屏硬件、中文
Narrator 环境不足、partial `SendInput` 无稳定实机复现、未测试架构和未签名。不得要求用户关闭
Defender 或其他系统保护来弥补未签名交付。

## 5. 发布后长测

首版实际发布后，按 [`../tasks/POST_RELEASE_SOAK.md`](../tasks/POST_RELEASE_SOAK.md) 对同一版本和
包校验和执行分段、24 小时和 72 小时会话。缺陷修复后发布补丁并建立新会话，不把旧版本失败记录
改写为通过。

## 6. 记录规则

- 当前跨阶段进度只更新 `docs/status/CURRENT_STATUS.md`。
- 实际命令、环境、输出和现场证据写入当前阶段的 `docs/records/` 文件。
- 完成阶段后将其任务和记录归档，再创建下一阶段记录；不预建跨阶段空记录模板。
- 开发完成、发布准备完成和已发布是三个不同状态，必须分别记录。
- 远端 tag、release 和附件操作必须有对应授权；文档或本地构建请求不等于发布授权。
